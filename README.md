## 维护

- `data/websites.json`：站名、网址、一句话简介、上线时间、时间依据、状态和源码仓库。`listed: false` 表示保留管理记录但不在门户重复展示自身。
- `data/repositories.json`：全部仓库、中文名称、简介、分类、可见性与归档状态。保留原项目地图的分类和人工说明。
- `scripts/build.py`：校验数据，生成 `dist/index.html` 和本文件中的目录区。
- `scripts/manage.py`：增删改站点、核对并同步 GitHub 仓库清单。

只需要 Python 3.10+；同步仓库另需已登录的 GitHub CLI。网页为静态 HTML/CSS/JS，不在浏览器请求私有 GitHub API。

```sh
python scripts/manage.py list-sites
python scripts/manage.py edit-site shuren --summary '阅读鲁迅作品，保存收藏与笔记。'
python scripts/manage.py add-site example --name '示例网站' --url 'https://example.liyw.top' --summary '一句话介绍。' --launch-date 2026-11-13 --launch-source '首次成功发布记录' --launch-verified
python scripts/manage.py remove-site example
python scripts/manage.py sync-repos
```

也可以直接编辑 JSON，再运行：

```sh
python scripts/build.py
python -m unittest discover -s tests -v
python scripts/build.py --check
node --check dist/app.js
```

网站按上线日期从新到旧排列，同日保持登记顺序；未知日期排在末尾。上线时间优先采用首次成功发布记录，只有 DNS 首次接入记录的使用 `launch_estimated: true`，网页显示「约」。仓库创建时间、内容涉及的年份和最后更新时间都不直接作为上线日期。

`repository` 填写本清单中的仓库名；暂未找到源码的使用 `null`，不会凭相似名称强行关联。仓库同步会保留人工名称、简介和分类；若移除的仓库仍被网站关联，校验将阻止写入，需先修正关联。

新建但尚未归档源码的仓库使用 `source_status: "repository_only"`；源码入库后可运行 `python scripts/manage.py edit-site city297 --source-status available` 更新状态。

每次维护命令都会同步生成网页和 README，提交前检查 Git diff。CI 会检查目录一致性、日期、源码关联、链接格式和生成结果。此 GitHub 仓库是唯一维护源；`.openai/hosting.json` 保留现有 Sites 项目身份，发布时同步本仓库对应提交至 Sites 源码镜像并上传 `dist/` 静态产物，访问权限沿用原门户设置。只提交 GitHub 不会自动改变线上版本。
